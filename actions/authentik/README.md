# Authentik

Manage users, groups and application access in an Authentik identity provider.

Generated from `spec.json` by `npm run gen`. Do not edit this file by hand.

## Package and install

```bash
npm run package -- authentik --url https://authentik.example.com
```

Upload `release/authentik-1.0.0.zip` in UserTasks: **Extensibility > Workflow actions > Upload**. Then open **Manage > Access** on the action:

1. Approve the host.
2. Set the secret `api_token`. Sent as a bearer token. Create it in the admin interface: Directory > Tokens and App passwords.

Recommended setup:

- A service account user for this connector
- An API token for that user (Directory > Tokens and App passwords, intent "API Token")
- A role that can view and change users and groups, and nothing more

The API schema of your server is at <server URL>/api/v3/schema/.

## Operations

Every operation also returns `http_status`, `http_ok` and `response` (the full body). A status that is not 2xx fails the step (429 and 5xx can be retried).

|---|---|---|---|
| `get_current_user` | Get Current User | `GET /api/v3/core/users/me/` | - |
| `search_users` | Search Users | `GET /api/v3/core/users/` | `search`?, `page_size`? |
| `get_user` | Get User | `GET /api/v3/core/users/{{user_pk}}/` | `user_pk` |
| `create_user` | Create User | `POST /api/v3/core/users/` | `username`, `name`, `email`, `is_active`? |
| `add_user_to_group` | Add User to Group | `POST /api/v3/core/groups/{{group_uuid}}/add_user/` | `group_uuid`, `user_pk` |

| `list_groups` | List Groups | `GET /api/v3/core/groups/` | `search`?, `page_size`? |
| `list_applications` | List Applications | `GET /api/v3/core/applications/` | `search`?, `page_size`? |
